ENGINEERING IMPACT

Technical Contributions

Rincian kontribusi rekayasa perangkat lunak backend yang saya kerjakan secara kolaboratif selama masa magang di BRI.

PILAR A

Backend API Development

  • Pengembangan REST API: Mengembangkan endpoint RESTful untuk dashboard Human Capital, query informasi talenta, master data, dan struktur hierarki organisasi.
  • Validasi Payload: Mengimplementasikan validasi request data secara defensif pada HTTP layer untuk mencegah request payload yang tidak valid masuk ke core logic.
  • Response & Error Handling: Menerapkan format envelope response JSON yang seragam (status, data, error) serta pemetaan kode status HTTP yang tepat.
PILAR B

Authentication & Access Control

  • Autentikasi JWT: Mengembangkan verifikasi token JWT untuk mengautentikasi sesi pengguna portal secara stateless dan aman.
  • Role-Based Access Control (RBAC): Membangun middleware otorisasi bertingkat untuk membatasi hak akses data antar peran pengguna (Administrator vs viewer).
  • Proteksi Akun: Mengembangkan penanganan validasi akun, pencegahan serangan brute-force dengan mekanisme account lockout sementara, dan proteksi credential.
PILAR C

Database & Query Optimization

  • PostgreSQL Data Access: Mengembangkan layer akses data relasional menggunakan PostgreSQL dengan parameterized query untuk mencegah SQL Injection.
  • Analisis Query via DBeaver: Menganalisis execution plan query pencarian talenta menggunakan DBeaver untuk menambahkan indeks kolom yang tepat dan mengeliminasi sequential scan.
  • Separation of Concerns: Menerapkan pemisahan tanggung jawab yang tegas antara Controller, Usecase, dan Repository agar logika bisnis independen dari driver database.
PILAR D

Code Quality & Security Testing

  • API Testing dengan Insomnia: Melakukan pengujian fungsional dan pengujian batas (boundary conditions) endpoint REST API secara konsisten menggunakan Insomnia.
  • Audit SonarQube & Checkmarx: Berkolaborasi dalam pipeline CI/CD untuk memastikan kode bebas dari code smell, bugs, dan celah keamanan SAST (Static Application Security Testing).
  • Refactoring Kode: Merapikan struktur penamaan variabel, penanganan context timeout, dan modularisasi fungsi untuk meningkatkan maintainability sistem.

DEEP DIVES

Technical Case Studies

Pendekatan penyelesaian masalah teknis dan hasil kualitatif faktual selama pengembangan.

Studi Kasus 1: Pemisahan Layer Kode & Pengurangan Ketergantungan Erat (Decoupling)

Clean Architecture

Tantangan Teknis: Pada awal pengembangan modul dashboard, kode handler HTTP kerap bercampur dengan query basis data langsung, menyulitkan proses penulisan unit testing dan meningkatkan risiko duplikasi logika bisnis.

Pendekatan Solusi: Menerapkan pola Clean Architecture dengan memisahkan kode menjadi lapisan Controller (Gin handler), Usecase (logika domain), dan Repository interface. Seluruh dependensi di-injeksi melalui konstruktor (Dependency Injection).

Hasil Faktual (Kualitatif): Struktur basis kode menjadi modular, memudahkan pengujian endpoint dengan mock repository, serta memastikan logika bisnis tidak terpengaruh saat skema database disesuaikan.

Studi Kasus 2: Otorisasi Berlapis & Keamanan Data Akses Talenta

JWT & RBAC

Tantangan Teknis: Sistem Human Capital memuat data sensitif pegawai yang hanya boleh diakses atau diubah oleh peran (role) tertentu sesuai hierarki organisasi bank.

Pendekatan Solusi: Mengembangkan middleware otentikasi JWT yang memvalidasi masa berlaku token dan mengekstrak claim peran pengguna pada setiap request. Menambahkan interceptor RBAC yang secara otomatis menolak akses jika role tidak memenuhi syarat izin endpoint.

Hasil Faktual (Kualitatif): Pengelolaan hak akses data talenta terlindungi secara terpusat, meminimalkan kebocoran data antar departemen, dan mempermudah audit izin akses sistem.

Studi Kasus 3: Kepatuhan Standar Keamanan & Audit SonarQube / Checkmarx

Code Quality & SAST

Tantangan Teknis: Di lingkungan perbankan, setiap kode yang diajukan ke staging wajib lolos gate audit SonarQube untuk code smell dan Checkmarx untuk celah keamanan statis (vulnerability scanner).

Pendekatan Solusi: Melakukan analisis mandiri pada hasil scan Checkmarx, memperbaiki potential memory leak pada handling context dan SQL connection, serta merapikan struktur penanganan error (no unhandled error returns).

Hasil Faktual (Kualitatif): Memenuhi standar quality gate yang ditetapkan tim enterprise architecture BRI dan menjaga kebersihan repositori dari celah keamanan mendasar.

Key Takeaways & Engineering Mindset

  • • Enterprise SDLC Standards: Memahami bahwa menulis kode di perbankan bukan sekadar membuat fitur berjalan, melainkan memastikan ketahanan, auditabilitas, dan kejelasan alur penanganan error.
  • • Defensive Backend Thinking: Setiap input dari klien harus divalidasi secara ketat sebelum diproses oleh database, serta context cancellation harus selalu ditangani untuk mencegah proses menggantung.
  • • Collaboration in Regulated Environments: Belajar berkoordinasi secara efektif antar tim frontend, DevOps, dan auditor keamanan perbankan.
